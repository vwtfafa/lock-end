# EndLock 3.1 — Integration Guide

Target audience: plugin developers who want to read EndLock's lock status or
react to lock state changes. This guide describes the **read-only** public API
shipped with EndLock 3.1. The authoritative contract is
[`3.1-api-contract.md`](3.1-api-contract.md); the live verification status is
documented in [`3.1-prototype-verification.md`](3.1-prototype-verification.md).

---

## 1. Overview

EndLock 3.1 publishes a small, **read-only** API in the package
`org.vwtfafa.lockEnd.api`. It contains exactly two public types:

| Type | Kind | Purpose |
|---|---|---|
| `EndLockApi` | interface, offered as a Bukkit service | Query the current runtime lock state (`isLocked()`) and the effective lock reason (`getLockReason()`) |
| `EndLockStateChangeEvent` | final event class | Notification of a **completed, successful** lock state change |

The API cannot lock or unlock the End. All state changes still flow through
EndLock's own commands, schedules, and undo logic, so history, broadcasts,
grace periods, and evacuations behave unchanged. The internal service
provider is not part of the API and carries no compatibility promise.

A consumer plugin such as a portal plugin, event plugin, or dashboard can:

- display whether the End is locked and why,
- start an event when the End opens,
- browse status changes without parsing EndLock's config files.

## 2. Getting the dependency

EndLock 3.1 ships the API classes inside its normal release jar. **There is
no Maven repository in 3.1** — you compile against the released jar
(from [GitHub Releases](https://github.com/vwtfafa/lock-end/releases) or
Modrinth) as a `compileOnly` dependency:

```kotlin
// build.gradle.kts of YOUR plugin
repositories {
    mavenCentral()
    maven { url = uri("https://repo.papermc.io/repository/maven-public/") }
}

dependencies {
    compileOnly("io.papermc.paper:paper-api:26.3.build.209-stable")
    // Downloaded release jar in a local libs/ folder of your project:
    compileOnly(fileTree("libs") { include("lock-end-3.1.0.jar") })
    // Alternative at runtime: declare EndLock in your plugin.yml (see below)
}
```

`compileOnly` only: the types serve compilation. At runtime, EndLock itself
provides the service — **never shade the API package into your plugin**.

Declare EndLock as an **optional runtime dependency** in your `plugin.yml`
so it loads before your plugin, without a hard dependency:

```yaml
name: YourPlugin
version: "1.0.0"
main: com.example.yourplugin.YourPlugin
api-version: "26.3"
folia-supported: true
softdepend: [EndLock]
```

## 3. Finding the service

Query the Bukkit `ServicesManager`:

```java
RegisteredServiceProvider<EndLockApi> registration =
        Bukkit.getServicesManager().getRegistration(EndLockApi.class);
EndLockApi api = registration == null ? null : registration.getProvider();
```

Rules:

- `registration == null` means **EndLock is not installed or is disabled**.
  This is a normal state, not an error — your plugin must keep running
  without integration.
- **Never cache the provider.** The service is unregistered when EndLock
  disables and re-registered when it enables. Resolve it fresh for every
  use (a small helper method like `api()` above is enough).
- The service is registered at priority `NORMAL`, so a plain
  `getRegistration(...)` lookup is correct. The lookup never throws; it only
  returns `null`.

While EndLock is disabled the API is simply unreachable — your code takes
the `null` branch. If you want to notice re-enables explicitly, listen to
the Bukkit `ServiceUnregisterEvent` (optional), but the simple
"query fresh every time" pattern already handles both directions safely.

## 4. `getLockReason()` contract

- Returns **plain text**: MiniMessage tags (`<...>`) and legacy `§` color
  sequences are **stripped**, not rendered. Unicode is preserved.
- The result is **never `null`**.
- With no configured reason, the same built-in fallback that blocked players
  see applies: `"Maintenance"`. If a configured reason becomes empty after
  stripping, the empty string is returned.
- The value is what a concurrently blocked player would see (minus any
  formatting).

Use it for display only; do not parse it as structured data.

## 5. Observing state changes

Register a normal Bukkit listener for `EndLockStateChangeEvent`:

```java
public final class LockStateLogger implements Listener {

    private final JavaPlugin plugin;

    public LockStateLogger(JavaPlugin plugin) {
        this.plugin = plugin;
    }

    @EventHandler
    public void onStateChange(EndLockStateChangeEvent event) {
        // Read-only: log or store the payload. See section 6 before
        // doing any world or player work.
        plugin.getLogger().info("End " + (event.newLocked() ? "locked" : "unlocked")
                + " by " + event.action());
    }
}
```

Contract:

- The event is **not cancellable**. It reports a change that already
  happened; you cannot prevent or revert it.
- It is fired **exactly once per successful state change**. It is **not**
  fired when the target state is already active, when the change fails, when
  the persisted state is restored at server start, when a pending schedule
  is merely registered, when `/endlock undo` has no recorded previous state,
  and on read-only paths such as blocked attempts.
- **Fields:**

| Field | Type | Meaning |
|---|---|---|
| `previousLocked()` | `boolean` | Lock state immediately before the change |
| `newLocked()` | `boolean` | Lock state after the change (always different from `previousLocked()`) |
| `action()` | `String` | Triggering action, see below |
| `actorName()` | `@Nullable String` | Display name of the acting sender, `"System"` for scheduled actions, `"CONSOLE"` for console commands; future callers may pass `null` |
| `actorUuid()` | `@Nullable UUID` | UUID of the acting entity; `null` for console and scheduled actors |

- **`action()` values:** the current documented set is `LOCK`, `UNLOCK`,
  `UNDO`, `SCHEDULED_LOCK`, and `SCHEDULED_UNLOCK`, but the set is **open**
  (forward compatibility). Compare tolerantly — e.g. switch on known values
  with a default branch; new values may appear in future 3.x releases.

**Listener lifecycle:** EndLock's reload/re-enable also unregisters your
listener's ability to receive its events (event handlers are removed with the
disabling plugin's registrations). If your plugin stays enabled across an
EndLock reload, **re-register your listener** afterward (e.g. on a
`PluginEnableEvent` for EndLock, or simply re-register on every
`ServerEvent`/reload point relevant to you). Registered listeners of *your
disabled* plugin are skipped at dispatch time anyway.

## 6. Thread and Folia rules

The event is **synchronous** — it fires in the tick context of the
triggering action and never from an async thread:

| Triggering action | Paper 26.3 | Folia 26.3 |
|---|---|---|
| Command by a player/entity | main thread | tick context of the region owning the actor |
| Console command | main thread | global region thread |
| Scheduled due action (`lockat`/`unlockat`/…) | main thread | global region thread |

Do **not** rely on a specific thread name. Treat the contract as:
"synchronous tick context of the triggering action".

For listeners:

1. **Read the payload only.** Consume the event fields inline; that is always
   safe.
2. **Do not mutate world or player state inside the handler.** On Folia in
   particular, never teleport, edit blocks or entities, touch scoreboards or
   portals inline. Use the **region/entity/global-region schedulers** for
   such work:

   ```java
   getServer().getGlobalRegionScheduler().run(myPlugin, task -> {
       // global work, e.g. console dispatch, shared state
   });

   player.getScheduler().run(myPlugin, task -> {
       // per-player work owned by the player's region
   }, () -> { /* retired, player left */ });
   ```

   These scheduler methods work identically on Paper 26.3 and Folia 26.3,
   so one code path supports both platforms. Never use
   `Bukkit.getScheduler()` if you want Folia compatibility.
3. A listener that throws does not prevent the state change (the error is
   logged), but it also cannot revert anything — the event is informational.

## 7. EndLock disabled / missing

- Your plugin must assume EndLock can be **absent** or **disabled at any
  time**. A missing service (`getRegistration(...) == null`) is the normal
  "no integration" state — degrade gracefully.
- Never throw during startup because EndLock is missing, and never
  `depend:` on EndLock unless your plugin is genuinely unusable without it.
  For a status display, `softdepend` plus fresh lookups is enough.
- Optionally listen to `ServiceUnregisterEvent` to log or pause your
  integration while EndLock is down; it is not required for correctness.

## 8. Full worked example

The verified reference implementation is the consumer prototype under
[`examples/api-consumer`](../examples/api-consumer) — it was live tested on
Paper 26.3 and Folia 26.3 Build 5 (ALPHA), see
[`3.1-prototype-verification.md`](3.1-prototype-verification.md). The
snippets below are adapted from it.

### 8.1 Build

```kotlin
// build.gradle.kts
plugins {
    java
}

group = "com.example"
version = "0.1.0"

repositories {
    mavenCentral()
    maven { url = uri("https://repo.papermc.io/repository/maven-public/") }
}

dependencies {
    compileOnly("io.papermc.paper:paper-api:26.3.build.209-stable")
    // The released EndLock jar provides org.vwtfafa.lockEnd.api:
    compileOnly(fileTree(mapOf("dir" to "libs", "include" to listOf("lock-end-3.1.0.jar"))))
}

java {
    toolchain.languageVersion.set(JavaLanguageVersion.of(25))
}

tasks.withType<JavaCompile>().configureEach {
    options.encoding = "UTF-8"
    options.release.set(25)
}
```

### 8.2 `src/main/resources/plugin.yml`

```yaml
name: EndLockIntegrationExample
version: "0.1.0"
main: com.example.endlockexample.EndLockExamplePlugin
api-version: "26.3"
folia-supported: true
softdepend: [EndLock]
```

### 8.3 The plugin class

```java
package com.example.endlockexample;

import org.bukkit.event.EventHandler;
import org.bukkit.event.HandlerList;
import org.bukkit.event.Listener;
import org.bukkit.plugin.RegisteredServiceProvider;
import org.bukkit.plugin.java.JavaPlugin;
import org.vwtfafa.lockEnd.api.EndLockApi;
import org.vwtfafa.lockEnd.api.EndLockStateChangeEvent;

import java.util.UUID;

public final class EndLockExamplePlugin extends JavaPlugin implements Listener {

    private static final long STATUS_TICK_INTERVAL_TICKS = 1200L; // 60 s

    @Override
    public void onEnable() {
        // Fresh startup probe only as a status check; every later use
        // resolves the provider again (never cache it).
        EndLockApi api = api();
        if (api == null) {
            getSLF4JLogger().info("EndLock not available - running without integration");
        } else {
            getSLF4JLogger().info("startup status: locked={}, reason={}",
                    api.isLocked(), api.getLockReason());
        }

        // Register the listener even when the service is missing: it also
        // proves robustness against an EndLock enabled later.
        getServer().getPluginManager().registerEvents(this, this);

        // Folia-safe periodic status tick (works on Paper too, no
        // Bukkit.getScheduler()).
        getServer().getGlobalRegionScheduler().runAtFixedRate(
                this, task -> logStatusTick(),
                STATUS_TICK_INTERVAL_TICKS, STATUS_TICK_INTERVAL_TICKS);
    }

    @Override
    public void onDisable() {
        HandlerList.unregisterAll((Listener) this);
    }

    /** Fresh lookup, never cached (EndLock disable/enable cycles). */
    private EndLockApi api() {
        RegisteredServiceProvider<EndLockApi> registration =
                getServer().getServicesManager().getRegistration(EndLockApi.class);
        return registration == null ? null : registration.getProvider();
    }

    private void logStatusTick() {
        EndLockApi api = api();
        if (api == null) {
            getSLF4JLogger().info("status tick: no service");
            return;
        }
        // getLockReason() is plain text, never null.
        getSLF4JLogger().info("status tick: locked={}, reason={}",
                api.isLocked(), api.getLockReason());
    }

    @EventHandler
    public void onStateChange(EndLockStateChangeEvent event) {
        String actorName = event.actorName();
        UUID actorUuid = event.actorUuid();
        // Payload only. Any world/player mutation belongs into a
        // Region/Entity/GlobalRegion scheduler, not inline here.
        getLogger().info("state-change: previousLocked=" + event.previousLocked()
                + ", newLocked=" + event.newLocked()
                + ", action=" + event.action()
                + ", actorName=" + (actorName == null ? "null" : actorName)
                + ", actorUuid=" + (actorUuid == null ? "null" : actorUuid));
    }
}
```

That is the complete integration: optional `softdepend`, fresh service
lookup, one listener, Folia-safe timers.

### 8.4 Re-registering after EndLock reloads

If your plugin should keep observing across EndLock reloads, re-register the
listener when EndLock (re-)enables:

```java
import org.bukkit.event.server.PluginEnableEvent;

// inside onEnable(), additionally:
getServer().getPluginManager().registerEvents(new Listener() {
    @EventHandler
    public void onPluginEnable(PluginEnableEvent event) {
        if (event.getPlugin().getName().equals("EndLock")) {
            // HandlerList.unregisterAll for the old listener first, then:
            getServer().getPluginManager().registerEvents(myStateListener, this$0);
        }
    }
}, this);
```

A dynamic provider lookup (`api()`) needs no such step — only listeners do.

## 9. API versioning and stability

- This is API version **"3.1"**, shipped with EndLock 3.1.
- It is the **first, read-only slice**: status queries plus one
  non-cancellable event. A write API (locking/unlocking through the API) is
  intentionally out of scope; future directions are tracked in
  [`ROADMAP-3.1.md`](../ROADMAP-3.1.md).
- Compatible 3.x changes: additional `action()` values (always parse
  tolerantly), additional nullable detail fields. Incompatible changes
  (signatures, fields, package) would require a new API version label.
- The `org.vwtfafa.lockEnd.api` package is a documented, supported surface.
  All implementing classes (the service provider) remain internal, without
  any compatibility promise.
